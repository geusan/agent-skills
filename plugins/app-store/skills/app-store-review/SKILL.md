# App Store 심사 준비

사용자가 지정한 앱·버전·출시 범위에 맞춰 필요한 항목을 처리한다. 업로드 성공, 심사 준비 완료, 심사 제출, 공개는 서로 다른 결과다. 아직 확인하지 않은 단계를 완료로 보고하지 않는다.

## 작업에 맞는 자료만 읽기

- 빌드·아이콘·현지화·스크린샷·Fastlane 오류: [fastlane.md](references/fastlane.md)
- 개인정보 화면, SDK 수집·목적·신원 연결·추적: [privacy.md](references/privacy.md)
- 콘텐츠 권한·연령 등급·암호화·가격·국가·심사 제출: [review-console.md](references/review-console.md)
- 이 대화의 히소히소 사례를 이어받는 경우만: [hisohiso-case.md](references/hisohiso-case.md)

이 문서의 경로는 스킬 디렉터리 기준이다. 앱 저장소와 스킬 저장소를 혼동하지 않는다.

## 시작할 때 확인할 것

1. 대상 저장소의 지침과 Git 변경 상태, bundle ID, Apple 앱 ID, 버전, 빌드 번호를 확인한다. 기존 미커밋 변경을 보존한다.
2. 요청을 **설명 / 로컬 수정 / TestFlight 업로드 / 스토어 설정 / 심사 제출 / 공개**로 구분한다. 이번 요청과 앞선 대화에서 이미 허용된 작업은 재승인을 요구하지 않는다. 업로드 요청을 심사 제출이나 공개의 허가로 확대하지 않는다.
3. 실제 제출할 빌드를 기준으로 기능과 SDK를 확인한다. 로컬 소스, 개발·staging·TestFlight·App Store 설정, 원격 기능 플래그가 다를 수 있다. 개인정보 값이나 권리 선언을 추정으로 채우지 않는다.
4. 기존 Fastlane lane과 인증 방식을 먼저 사용한다. 자격증명은 기존 비밀 파일·환경에서 읽고, 로그·스킬·Git에는 넣지 않는다.
5. 정책·UI·API 지원처럼 변하는 정보는 해당 reference의 Apple/Fastlane/SDK 공식 문서로 확인한다. 과거 대화의 선택값은 근거를 대신하지 않는다.

## 진행 방식

### 사용자가 콘솔 화면을 보내는 경우

질문의 **데이터 유형과 단계**를 먼저 읽는다. 이메일의 사용 목적과 기기 ID의 신원 연결 여부는 별개 질문이다.

- 근거가 있으면 **선택할 항목 + 한 문장 이유**로 답한다.
- 같은 기준을 방금 검증했다면 반복 검색하지 않는다.
- 실제 운영 방식에 따라 답이 달라지면 차이를 짧게 설명하고 필요한 사실을 확인한다. 확인 가능한 코드·배포 설정은 먼저 조사한다.
- 스크린샷에서 사용자가 선택한 값은 정확성의 증거가 아니다.
- 오류를 발견하면 이전 답변을 명확히 정정하고 영향을 받는 다른 항목도 정리한다. 사용자의 지적만으로 반대 답을 단정하지 않는다.
- “추적하지 않음”과 “사용자와 연결되지 않음”, “음성 전송”과 “Apple 정의상 수집”을 혼동하지 않는다.

### 실제 준비·업로드 요청인 경우

필요한 파일을 수정하고 검증한 뒤 허용된 원격 작업까지 수행한다. 메타데이터·스크린샷만 바꿨다면 바이너리를 불필요하게 다시 올리지 않는다. 앱 내 라이선스 안내·아이콘·SDK 변경은 새 빌드가 필요하다.

일부 필수 정보가 없어도 독립적으로 처리할 수 있는 일은 계속한다. 지원 URL, 권리자명, 법적 권한, 개인정보 답변을 지어내서 필수칸을 통과시키지 않는다.

프로젝트에 맞는 검증을 실행한다. 실패가 발견되면 관련성과 해당 빌드의 위험을 평가해 해결하거나 미해결 상태를 명시한다. 실패를 숨기거나 “검증 완료”로 요약하지 않는다. 내부 베타 업로드 성공은 정식 심사 적합성의 증명이 아니다.

## 완료 근거

필요한 범위만 대상 저장소의 배포 문서에 기록한다.

| 항목 | 기록할 근거 |
|---|---|
| 빌드 | 버전·빌드 번호, 아티팩트, 업로드 성공과 Apple 처리 상태 |
| 메타데이터 | 언어·필드별 로컬 값과 원격 재조회 결과 |
| 스크린샷 | 승인된 기기·언어·장수, 원본 해시, 원격 처리 상태 |
| 개인정보·콘텐츠 권한 | 실제 제출 빌드, 확인한 코드·운영 정보, 사용자 제공 사실, 미확정 내용 |
| 연령·가격·국가 | 설정한 값, 현재 상태, 사용자가 지정한 향후 계획 |
| 남은 일 | 지원 URL·연락처·권리·신고·새 빌드 등 실제 미완료 항목 |

마지막 답변은 **완료한 것 / 확인한 것 / 남은 것**을 구분한다. 실제 심사에 제출하지 않았다면 “제출 완료”라고 쓰지 않는다.
