# 개인정보 신고: 실제 제출 빌드로 판단

## 데이터 흐름부터 확인

흐름마다 **유형 / 발생 조건 / 기기 밖 수신자 / 보관 기간 / 동반 식별자 / 용도 / 데이터 결합 / 근거 / 미확정 사실**을 기록한다. UI 체크박스부터 정하지 않는다.

근거는 코드, 잠금 파일과 SDK 개인정보 명세, 제출 빌드 설정, 서버 저장·로그, 서비스 콘솔, 실제 정책 페이지다. SDK 설치와 기능 활성화는 구분한다. custom event에서 PII를 막아도 SDK 자동 수집이 사라지지 않는다.

확인할 경로:

- 분석 SDK 자동/사용자 정의 이벤트, 설치 ID, 지역 추정, 광고·공유 설정
- 오류 보고 이미지·텍스트·로그·세션 번호·기기 식별자·서버 접근 로그
- 마이크·사진 사용과 실제 업로드, provider·endpoint, 임시 처리와 보관
- 지원 메일·첨부, 계정·프로필, 알림·구매·광고 등 실제 사용 기능

표시되는 데이터 유형 전체를 검토한다. 미리 작성된 유형 몇 개만으로 신고가 완성됐다고 하지 않는다.

## 수집 / 신원 연결 / 추적은 세 질문

### 1. Apple 정의상 수집하는가

기기 안에서만 처리하는 데이터는 이 신고의 수집에 해당하지 않는다. 외부 전송된 데이터를 개발자나 제3자가 실시간 요청 처리에 필요한 시간보다 오래 접근할 수 있다면 수집에 해당한다.

전송만 보고 수집으로 단정하거나, “서버 DB 저장 없음”만 보고 미수집으로 단정하지 않는다. 외부 provider·proxy·로그·오류 수집·보관 설정도 확인한다. “학습에 쓰지 않음”은 “보관하지 않음”과 다르다.

선택적 고객지원/피드백도 자동 면제되지 않는다. Apple optional disclosure 조건 전체를 확인한다. 불규칙하고 선택적인 부가 기능, 추적/광고 등에 미사용, 제출 내용의 명확한 표시, 매번 명시적 제출 및 제출 양식의 이름/계정 표시 등 조건이 있다. 일부 조건만 맞으면 면제를 가정하지 않는다.

### 2. 사용자 신원과 연결되는가

실명·로그인 유무만으로 결정하지 않는다. 계정·고정 설치/기기 식별자·메일 주소·사용자 세부정보와 연결되는지 확인한다. 해시나 가명 ID라는 이유만으로 연결이 사라지지 않는다.

임시 보고서 UUID, 기종, OS만 있다면 고정 사용자 연결과 다를 수 있지만 이것만으로 익명성을 보장하지 않는다. 이미지·자유 입력, IP/서버 로그, 이메일 첨부 등의 다른 수집 경로와 재연결 여부를 함께 검토한다. 수집 전 비식별화와 재연결 방지가 확인되어야 미연결 답변을 뒷받침할 수 있다.

한 유형의 모든 수집 경로를 포함해 답한다. SDK 스크린샷을 식별자 없이 보내더라도 동일 유형의 지원 메일 첨부사진을 이메일과 보관하면 그 경로도 고려한다.

### 3. 추적에 사용하는가

Apple tracking은 타사 앱·웹사이트·오프라인 출처와 연결한 타깃 광고/광고 효과 측정 또는 데이터 브로커 공유 등이다. 단순 이용 통계, 같은 앱 안의 요청 연결, 남용 방지만으로 추적이라고 하지 않는다.

반대로 자체 광고가 없거나 IDFA를 껐다는 이유만으로 모든 partner의 추적이 없다고 단정하지 않는다. SDK와 서비스의 공유·광고 연결 설정을 확인한다. 추적이나 IDFA 접근이 필요하면 ATT와 공개 답변을 함께 검토한다.

## 유형·목적 판단 예시

| 확인된 흐름 | 검토할 유형 | 목적 판단 |
|---|---|---|
| 문의 이메일·표시 이름 | 이메일 주소·이름, 고객 지원 | 지원에만 사용하면 앱 기능 |
| 분석용 앱 설치 ID | 기기 ID | 분석; 인증·남용 방지에도 쓰면 앱 기능 추가 |
| 화면 조회·학습 시작/완료 | 제품 상호 작용 | 이용 현황·기능 효과 평가라면 분석 |
| 요청 횟수·사용량 제한 | 실제 필드에 따른 식별자·상호작용 등 | 기능 제공·보안·남용 방지는 앱 기능 |
| 오류 제보 스크린샷·설명 | 사진 또는 비디오·고객 지원 | 문제 해결은 앱 기능 |
| 기기·OS·네트워크·오류 상태 | 기타 진단 데이터 | 안정성 개선·고객지원은 앱 기능 |
| crash report·stack trace | 충돌 데이터 | 실제 수집 확인; 오류 메시지와 동일시하지 않음 |
| 실행 지연·hang·에너지 사용 지표 | 실적 데이터 | 실제 측정/전송 확인; 외부 음성 서버 지연도 검토 |
| 외부 처리/보관 녹음 | 오디오 데이터 | 인식·답변 확인은 앱 기능; 보관 예외 먼저 검토 |
| IP 기반 지역 정보 | 대략적인 위치 등 | GPS 권한과 별개로 SDK·콘솔 확인 |

표는 기본 선택값이 아니다. 실제 흐름에 해당하는 유형만 고른다. 지원 텍스트를 이유 없이 이메일/문자·기타 사용자 콘텐츠에도 중복 신고하지 않는다. 기술적 오류를 분석한다고 무조건 “분석” 목적을 고르지 않는다. 사용자 행동·기능 효과·이용자 규모 평가와 기능 안정성 개선을 구별한다.

## 음성 API가 있는 앱

- 제출 빌드의 endpoint·인증·feature flag·fallback을 확인한다. 내부 배포에서 동작한 경로가 TestFlight에서도 동작한다고 가정하지 않는다.
- endpoint를 코드로 확인하고 provider의 최신 보관 정책을 확인한다. OpenAI 음성 전사, 음성 생성, Realtime 등의 정책을 서로 대입하지 않는다.
- 2026-09-16 확인 사례에서 `/v1/audio/transcriptions` 공식 문서는 abuse-monitoring 및 application-state retention을 `None`으로 표기했다. 이후 판단 때 다시 확인한다. 조직의 데이터 공유 설정·별도 저장도 포함한다.
- 원본 음성·전사문을 폐기해도 설치 ID·문항 ID·길이·지연·오류·사용량을 보관하면 그 메타데이터는 별도 평가한다. 원본 미수집 판단이 모든 관련 데이터의 미수집을 뜻하지 않는다.
- 제3자 처리 안내·동의와 개인정보처리방침은 App Store 체크박스와 별도다. 미확정 운영 방식을 대신 선언하지 않는다.

## 입력·자동화·확인

UI에서는 **앱 개인정보 → 유형 → 각 유형의 용도 → 신원 연결 → 추적 → 저장 → 게시 상태 확인** 순으로 진행한다. 현재 질문만 간결하게 안내하되 새 사실이 앞선 답변에 영향을 주면 수정한다.

Fastlane에서는 검토한 JSON을 `upload_app_privacy_details_to_app_store(json_path: ...)`에 전달할 수 있다. 현재 공식 안내는 소유자/관리자 Apple ID 인증을 요구하며 ASC API 키를 지원하지 않는다. 설치 버전의 동작을 읽는다. 기존 답변을 삭제·대체하거나 자동 게시할 수 있으므로 원격 답변을 보관하고 사용자가 요청한 저장/게시 범위에 맞춰 `skip_publish` 등을 설정한다.

원격 조회나 인증이 불가능하면 초안·근거·입력 순서를 완성한다. 저장/게시가 확인되지 않으면 완료라고 하지 않는다.
