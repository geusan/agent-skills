## 동작 특성과 미완료 항목

- 빌드 4에는 로컬 Screen Reporter `0.1.3-dev.1` override가 포함됐다. 출시 재현성을 위해 원격 릴리스 태그와 로컬 변경을 구분한다.
- 전체 테스트는 당시 540개 통과·4개 실패였다. 번역 강조 2개, 테스트 환경 오디오 플러그인 1개, 계층 의존성 규칙 1개였다. 이후 해결 여부를 다시 검사한다. 정적 분석은 보조 스크립트 info 3건이었다.
- KanjiVG 출처·원본 저작권·CC BY-SA 3.0 URL·변경 및 동일 라이선스 안내를 `lib/src/screens/settings.dart`의 **설정 → 도움말 및 의견 → 오픈소스 정보**에 추가했다. 해당 파일 분석과 기존 설정 테스트를 통과했다. 이 수정은 빌드 4 업로드 후의 소스 변경이며, 새 빌드에 넣어야 앱에 반영된다.
- 지원 URL, review contact/notes, 최종 개인정보 게시, 연령 등급, 콘텐츠 권한, 가격·지역·빌드 연결은 현재 원격 상태를 재조회한다. 콘솔 화면별 선택 안내를 실제 저장으로 기록하지 않는다.
- 당시 스토어 버전 `1.1.0`의 빌드 연결과 store icon이 비어 있음을 API로 확인하고 빌드 4 선택 방법을 안내했다. 이후 사용자가 저장했는지는 별도 확인이 필요하다.
- 전체 메타데이터 첫 시도는 이전 앱 이름 `Oboero`로 새 언어를 추가하다 이름 중복 오류가 났다. 한국어 이름을 요청값으로 먼저 갱신하고 재시도했다. 이어서 Fastlane 2.239.0이 빈 review attachment 응답의 `No data`로 종료했지만 메타데이터 12개 필드는 모두 원격 값과 일치했다.

## 개인정보에서 다시 확인해야 할 점

이 세션에서 도출한 선택값을 그대로 JSON으로 게시하지 않는다.

- Firebase Analytics는 실제 연동되어 있다. 광고 ID/광고 동의와 IDFV 수집을 끄는 설정이 있어도 app-instance ID와 이벤트 수집은 별개다. 콘솔의 지역·공유 설정까지 확인해야 한다.
- Screen Reporter는 사용자가 전송한 스크린샷·설명·기기/OS/네트워크 상태를 처리한다. 임시 UUID만 보고 모든 이미지가 신원과 무관하다고 확정하지 않는다. 내용과 이메일 첨부 경로도 고려한다.
- 앱에는 `앱 → Cloudflare → OpenAI 음성 전사` 경로가 있다. 다만 당시 확인한 TestFlight lane은 `env.private.json`을 주입하지 않고 공개 env에 speech endpoint/bootstrap이 없었다. 내부 배포와 출시 버전의 실제 활성화를 다시 확인해야 한다.
- 확인한 서버 소스는 원본 음성·전사문 대신 설치 식별자·문항·요청 ID·길이·지연·비용·오류 등 사용량 지표를 저장했다. 운영 환경·provider의 보관 정책은 코드만으로 확정할 수 없다.
- “오디오는 기기 내 처리라 해제”라는 초기 안내는 외부 처리 경로를 충분히 구분하지 못한 답변이었다. 전송과 보관을 확인하고 Apple 실시간 처리 예외로 평가한다.
- “실적 데이터 없음”도 cloud provider 지연 기록 등을 포함한 최종 출시 경로로 다시 평가해야 한다.
- 과거 `docs/legal/store-privacy-disclosures.ko.md`의 “분석 SDK 없음” 전제는 잘못된 상태라 사용 금지 안내를 추가했다. 해당 표를 제출 초안으로 재사용하지 않는다.

## 사용자가 콘솔을 진행한 흐름

메타데이터·스크린샷 → 개인정보 유형/용도/신원 연결/추적 → 콘텐츠 권한 → 연령 등급 → 암호화 → 가격·사용 가능 국가 순으로 안내했다. 향후 광고 추가 시 광고/개인정보/ATT를, 친구 간 순위 경쟁 추가 시 시합 빈도 등을 변경해야 함을 설명했다. 이는 실제 미래 기능을 구현하거나 현재 공개 설정을 변경하라는 요청은 아니었다.
