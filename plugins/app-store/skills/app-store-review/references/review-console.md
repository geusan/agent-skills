# App Store Connect 심사 설정

## 필수 항목과 입력 주체

| 항목 | 필요한 사실/처리 |
|---|---|
| 기본 카테고리 | 앱의 실제 주 기능과 사용자 선택 |
| 지원 URL | 사용자가 도움·문의 정보를 찾을 수 있는 공개 페이지 |
| 개인정보처리방침 URL | 실제 수집·처리자·보관·권리 행사에 맞는 공개 문서 |
| 저작권 | 연도와 실제 권리자 표기 |
| 콘텐츠 권한 | 사용·표시·접근하는 외부 콘텐츠 목록과 권리 근거 |
| 앱 개인정보 | 대상 빌드와 운영 설정을 바탕으로 작성·게시 |
| 연령 등급 | 실제 노출되는 기능·콘텐츠·빈도·약관상 연령 제한 |
| 암호화 | 앱과 포함 라이브러리의 비면제 암호화 여부 |
| 가격·국가 | 사용자 사업 방침, 현재/향후 출시 범위 |
| 심사 정보 | 로그인 필요 여부, 실제 연락처, 재현 가능한 기능 설명 |
| 제출 빌드 | 심사할 버전에 올바른 빌드를 선택하고 처리 상태 확인 |

필수 URL을 임의의 주소로 대체하거나 심사 담당자의 이름·전화번호를 만들어내지 않는다. 로그인 없는 앱에 불필요한 테스트 계정을 만들지 않는다. 모델 다운로드·권한·특정 기능 진입 등 심사자가 실제로 알아야 할 조건은 review notes에 정확히 설명한다.

## 콘텐츠 권한과 라이선스

자체 저작권 표기와 타사 콘텐츠 권한은 다르다. 데이터셋·필순·이미지·폰트·영상·오디오·모델 등 포함하거나 접근하는 자산의 실제 라이선스와 허가 범위를 확인한다. 오픈 라이선스 콘텐츠도 타사 콘텐츠다.

- 외부 콘텐츠가 있고 필요한 권리/법적 허가가 확인되면 “타사 콘텐츠를 포함/표시/접근하며 필요한 권한이 있음”에 해당한다.
- 전부 자체 제작이라고 검증되지 않았다면 “타사 콘텐츠 없음”을 편의상 고르지 않는다.
- 사용자의 권리 확보 진술을 기록해 활용하되, 한 자료의 라이선스 확인을 다른 모든 자료의 권리 확인으로 확대하지 않는다.
- 출처 고지는 실제 앱에서 접근할 수 있도록 기존 설정·라이선스 화면에 추가한다. 저작물명, 저작권자, 출처, 라이선스 링크와 변경 여부 등 해당 조건을 반영한다.
- 예: KanjiVG의 CC BY-SA 3.0은 상업 이용·수정을 허용하지만 표시, 수정 자료의 동일 라이선스 제공 등 조건이 따른다. 원본에 기재된 저작권을 보존하고 변경 범위를 표시한다. 전체 앱 코드의 라이선스를 임의로 바꾸지 않는다.
- 라이선스 UI를 수정했다면 현재 배포 빌드에 자동 반영되지 않는다. 변경을 포함한 새 빌드로 검증·배포해야 한다.

## 연령 등급

앱 카테고리만으로 모든 답을 “없음”으로 정하지 않는다. 실제 출시 기능, 내장/원격 콘텐츠, 문장·단어·영상의 민감 주제와 노출 빈도를 검토한다. 미래 기능은 구현되어 출시될 때 갱신한다.

| 질문 | 판단 기준 |
|---|---|
| 유해 콘텐츠 차단/보호자 통제 | 실제 부모·보호자의 모니터링·제한 기능이 있는가 |
| 나이 확인 | 실제 연령 확인 수단/API/절차가 있는가 |
| 제한되지 않은 웹 접근 | 앱 안에서 임의의 웹페이지를 자유 탐색할 수 있는가; 고정 링크와 구분 |
| 사용자 생성 콘텐츠 | 사용자가 만든 콘텐츠를 앱 경험의 일부로 널리 배포하는가; 비공개 버그 보고와 구분 |
| 소셜 미디어 | 피드·발견·재배포 등 실제 social 기능이 있는가; 친구 목록만 보고 단정하지 않음 |
| 13세 미만 social 제한 | 해당 기능과 현재 Apple이 요구하는 연령 확인/제한 구현을 확인; social이 없으면 “제한 구현됨”을 주장하지 않음 |
| 메시지·채팅 | 사용자끼리 직접 대화할 수 있는가 |
| 광고 | 현재 앱에 유료 홍보가 표시되는가 |
| 시합 | 사용자끼리 순위·보상·목표 달성을 위해 경쟁하는가 |
| 가상 도박·도박·랜덤 박스 | 실제 베팅, 현금/환금성, 유료 무작위 아이템 구조를 각각 검토 |

혼자 쌓는 스트릭·레벨과 친구 간 순위 경쟁은 다르다. 친구 리그/랭킹을 넣으면 시합 여부와 실제 접하는 빈도를 다시 평가한다. 순위 경쟁만으로 도박이라고 하지 않는다.

광고 추가 시 광고 답변뿐 아니라 SDK 개인정보, 처리방침, tracking/ATT를 갱신한다. 광고가 있다고 자동으로 tracking이라고 답하지 않는다.

계산된 `4+`와 “어린이용” 지정은 다르다. 어린이 전용 앱이 아닌데 낮은 등급만 보고 Kids로 지정하지 않는다. 이용약관에 실제 최소 연령이 있는지 확인한 후 override를 결정한다. 보호자 도움을 권장하는 안내와 서비스 자체의 이용 연령 제한을 구분한다. 선택적 연령 적합성 URL에 무관한 페이지를 넣지 않는다.

## 암호화 문서

문서 업로드 버튼이 보이는 것과 업로드가 필수인 것은 다르다. 프로젝트와 IPA의 `ITSAppUsesNonExemptEncryption`을 확인한다.

`false`는 비면제 암호화가 없다는 **선언**이다. 값 자체가 판단 근거를 증명하지 않는다. 앱과 SDK의 암호화 구현, 네트워크 transport, 번들된 라이브러리와 export 요건을 확인한다. HTTPS라는 이유만으로 Apple OS 암호화만 쓴다고 단정하지 않는다. OS에 포함된 암호화의 일반적인 문서 면제 사례와 직접 포함한 암호화 구현을 구별하고 공식 결정 절차를 따른다.

파일 무결성 해시를 독자 암호화와 혼동하지 않는다. 서버의 암호화와 배포 바이너리의 암호화를 구분한다. 문서 면제와 다른 국가별 신고 의무가 모두 없다는 주장도 구별한다.

## 가격·국가·법인

- 무료/유료를 먼저 확인한다. 예시로 무료를 안내했다고 실제 가격을 0원으로 바꾸지 않는다.
- 무료 앱과 유료 앱/인앱결제 계약 조건을 구분한다. 법인이 없다는 이유만으로 개인 개발자의 무료/유료 배포가 모두 불가능하다고 말하지 않는다. 유료 제공에는 해당 계약·세금·은행 정보가 필요하다.
- 한국어 현지화만 남기는 것과 대한민국에만 배포하는 것은 별도 변경이다. “우선 한국, 나중에 전체”라면 현재는 한국만 선택하고 향후 확대 계획을 기록한다. 미래 계획을 현재 전 세계 공개로 실행하지 않는다.
- 조직 명의가 필요하면 법적 실체·D-U-N-S 등 최신 등록 조건과 개인→조직 전환 경로를 확인한다. 개인 계정의 판매자명, 저작권 필드, 앱 이름은 서로 다르다.
- 저작권 필드에 회사명을 써도 조직 계정으로 전환되지 않는다. 미설립 회사의 법적 지위를 대신 확인하지 않는다. 현재 준비·TestFlight·심사·공개 중 어디까지 진행할지 사용자 지시를 따른다.

## 제출 전 마무리

1. 원격 편집 버전, 선택한 빌드, locale, 필수 URL·권리·연령·개인정보 게시·가격·국가 상태를 다시 확인한다.
2. 출시 후보에 라이선스 안내와 실제 신고한 기능이 들어 있는지 확인한다. 향후 구현 예정 답변으로 현재 바이너리를 설명하지 않는다.
3. 테스트 실패, 재현되지 않은 핵심 기능, 로그인·네트워크·모델 설치 조건을 명확히 남긴다. 업로드 성공으로 심사 적합성을 대체하지 않는다.
4. 사용자가 심사 제출을 요청한 범위에서만 제출한다. 공개 방식도 기존 설정과 사용자 의사를 확인한다. 저장/빌드 연결은 제출·공개와 다르다.
5. 사용자에게 자동화가 못 처리한 실제 항목만 안내한다. 제출 오류가 나면 기존 원격 상태와 정확한 오류를 기준으로 복구한다.
